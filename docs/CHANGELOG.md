# 本地变更记录

## 1.3.5 — 2026-11-11

- 新增开机 / 登录 / 睡眠唤醒宽限期（180 秒），起点取开机时间、当前用户最早 explorer 进程、watch 检测到的唤醒（检查间隔 > 60 秒）三者中最晚的一个。尚无用户登录时始终处于宽限期。
- 宽限期内，`$RiskInfo` 中明确登记为中 / 低危的异常（内核、TUN、守护、助手、检查出错）不计入连续计数、不锁定，每个宽限窗口只记录一条 `grace` 事件。高危异常和未登记类型照常计数并锁定（fail closed）；宽限期结束后代理仍未就绪的，按原流程锁定。
- guard / status 新增 `grace_until`（guard 另有 `grace_noted`），用 `Add-Member -Force` 写入。工作台显示宽限期状态，保护记录新增“宽限暂缓”类型。
- 修复依据：本机 11 次开机中有 6 次在约 45 秒后被误锁，原因是 SYSTEM watch 先于用户登录后才启动的 FlClash / ClaudeGuard 开始检查；此时断网规则已在生效，锁定没有增加保护。
- 新增 9 项 PowerShell 宽限期回归、3 项工作台回归。

## 1.3.4 — 2026-11-05

- Store 包选择先核对 Installed 注册，再按版本排序，统一身份、风险及进程目录判断；Staged 更新不再误锁，真正安装新版未覆盖时继续拦截。
- Global 状态互斥锁显式授权 SYSTEM 与管理员，保持原锁名和串行语义，修复默认 DACL 导致的跨主体 AccessDenied。
- 隔离提示限定为“清单内程序”，当前异常未恢复时不暗示已通过。
- 新增 Store 生命周期和实际局部 Mutex ACL/释放回归。

## 1.3.3 — 2026-11-03

- 锁定期间程序清单扩展时，只添加缺失逐程序 DENY，保留已有规则和锁定。
- 基础保护与 Claude 隔离分开核验，status schema 3 提供各自计数，允许保留额外旧 DENY。
- 人工解除要求非空白名单、两项出口成功取得并匹配，放开前再次检查当前 Desktop/CLI 身份。

## 1.3.0–1.3.2 — 2026-10-31

- 深色三页工作台、连续确认后隔离、人工解除、结构化保护记录。
- watch 改为常驻循环，计划任务作为看门狗，消除反复启动造成的检查断档。
- ClaudeGuard runtime 本地补丁：网络拦截继续立即请求，进程结束按危险级别处理；高危立即结束，中低危持续 10 秒后处理，记录断网/结束/恢复。

## 1.1.0–1.2.0 — 2026-10-29

- 未知和过期状态不报绿色；核对 IPv4/IPv6 规则及采集错误恢复。
- 严格路由采用同 owner 下 DNS block/protect 的动态 WFP 运行时证据，不依赖固定 owner 名称或只看配置文件。
- 200% 缩放布局、固定操作栏与可滚动区域、危险操作提示。
